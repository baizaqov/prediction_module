# T-12–T-13 · История и безопасная правка весов

**Дата фиксации:** 2026-08-14
**Статус:** реализовано и проверено на локальной SQLite test-БД.

## Реализация

- Добавлена append-only сущность `bb_risk.factor_weight_change`: нозология, номер
  фактора, старый и новый веса, автор из `Principal` и время UTC.
- ORM запрещает обновление и удаление уже созданной истории; сервис и API не содержат
  операций её правки или удаления.
- Добавлен `PATCH /v1/risk/infections/{infectionCode}/factors/{factorNo}/weight` с
  телом `{"weight": 1..4}`. При включённой JWT-проверке запрос без JWT получает
  `401`; изменить вес может только `gisbb_expert`, остальные аутентифицированные
  пользователи получают `403 ACCESS_DENIED`.
- Фактическая правка меняет `Factor.weight` и добавляет ровно одну историю в одной
  транзакции. Повтор текущего веса возвращает `200` без изменения данных и истории.
- Снимок `AssessmentScore.weight` и сохранённый результат оценки не пересчитываются.

## Миграция

Подготовлена ручная миграция:

```text
e4c3f9a7b812 -> a7d9b6c4e281
```

Она создаёт `bb_risk.factor_weight_change` и индекс по нозологии и номеру фактора.
Миграция **не применялась** к `gisbb_db` или другой удалённой БД.

## Проверки

- `tests/test_risk_weight_history.py`: `14 passed`.
- Полный набор риск-тестов: `47 passed`.
- Проверены успешная правка Экспертом, `401` без JWT, `403` для КСЭК/КВКН/МИО,
  обычных write- и read-ролей, диапазон 1–4, атомарность, одна история на правку,
  append-only поведение и неизменность снимка старой оценки.

## Ожидаемые решения методологов

Не относятся к реализованной операции весов, но остаются открытыми: окончательная
матрица «фактор → один или несколько органов», состав панелей, машиночитаемые границы
шкал, правила сведения периодов и актуальности дублирующих оценок.
