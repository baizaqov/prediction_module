# T-22 · Карточка сохранённой оценки — завершение

Дата: 2026-08-14

## Реализовано

Добавлен read-only endpoint `GET /v1/risk/assessments/{assessmentId}`
(через gateway — `/api/forecast/v1/risk/assessments/{assessmentId}`). Он использует
тот же `READ_ROLES`, что и журнал оценок.

Ответ содержит идентификатор, нозологию и её название, регион, период, панель, дату
создания, сохранённые итоги (`panelSize`, `assessed`, `integralIndex`, `completeness`,
`adjustedIndex`, `level`, `levelRu`, `hasRedTrigger`) и упорядоченный список `scores`
с `factorNo`, `score`, `weight`.

Агрегаты читаются только из `bb_risk.assessment`, а баллы и веса — только из
`bb_risk.assessment_score`. Расчёт не запускается, текущий `Factor.weight` не читается.
Строки баллов не соединяются с каталогом факторов, поэтому удалённый фактор остаётся
в истории. Для отсутствующей оценки возвращается `404 NOT_FOUND` через `ForecastError`.

Схема БД достаточна: новая миграция не создавалась и не применялась.

## Проверка

- `tests/test_risk_assessment_detail.py`: 4 passed.
- Все risk-тесты (`tests/test_risk_*.py`): 51 passed.

Оба запуска выполнены только на локальной SQLite test-БД. Тесты проверяют успешную
карточку и совпадение с `Assessment`/`AssessmentScore`, `404`, независимость от
последующей правки текущего веса и сохранность строки после удаления фактора из каталога.

## Оставшиеся решения методологов

T-22 не блокируется внешними решениями. Для следующих задач по-прежнему требуются:
окончательная матрица «фактор → орган», состав обязательной и дополнительной панелей,
машиночитаемые границы шкал, правило сведения периодов и правило актуальности нескольких
оценок за один период.
