# T-14–T-16 · Временное ролевое разграничение факторов

**Дата фиксации:** 2026-08-14
**Статус:** реализовано и проверено на локальном backend с тестовой БД.

## Принятое временное решение

До получения окончательной матрицы методологов используется Приложение 4 для
бруцеллёза:

| Орган | Факторов |
|---|---:|
| КСЭК | 20 |
| КВКН | 13 |
| МИО | 13 |
| Эксперт госоргана | все 46 |

Матрица хранится отдельно от свободного текстового поля `Factor.responsible`.

## Реализация

- T-14: добавлены подтверждённые Keycloak-роли Эксперта, КСЭК, КВКН и МИО в
  `READ_ROLES` и `WRITE_ROLES`; прежние роли сохранены для обратной совместимости.
- T-15: добавлены сущности `bb_risk.organization` и
  `bb_risk.factor_organization`. Связь many-to-many позволяет назначать одному
  фактору несколько органов без изменения авторизационного кода.
- T-16: `GET /v1/risk/infections/{code}/factors` фильтруется по текущей роли;
  `POST /v1/risk/assessments/preview` и `POST /v1/risk/assessments` отклоняют
  баллы по чужим факторам до расчёта и сохранения. `GET /v1/risk/assessments`
  намеренно не ограничивается.

## Миграция тестовой БД

Применена вручную к тестовой `gisbb_db`:

```text
9957c584c186 -> e4c3f9a7b812
```

После применения подтверждено read-only запросом:

- созданы таблицы `bb_risk.organization` и `bb_risk.factor_organization`;
- матрица бруцеллёза содержит 46 уникальных факторов;
- распределение: КСЭК 20, КВКН 13, МИО 13.

## Проверки

- В `gisbb_keycloak`, realm `gisbb`, подтверждены все девять используемых
  ролей; у каждой есть назначение как минимум одному пользователю.
- Риск-тесты SQLite: `33 passed`; отдельный набор T-14–T-16: `18 passed`.
- На локальном backend с включённой проверкой внутреннего JWT:
  - запрос без JWT получает `401`;
  - КСЭК видит 20 факторов;
  - КВКН видит 13 факторов;
  - МИО видит 13 факторов;
  - Эксперт видит 46 факторов;
  - preview КСЭК с чужим фактором получает `403 ACCESS_DENIED`;
  - сохранение КСЭК со своим и чужим фактором получает `403 ACCESS_DENIED`;
    для проверочного региона не созданы ни `Assessment`, ни `AssessmentScore`.

## Что остаётся временным

Окончательная матрица методологов пока не получена. Для её замены нужны данные
вида «нозология, номер фактора, один или несколько органов». Их следует
применить миграцией данных к `bb_risk.factor_organization`; бизнес-логику и
проверки API переписывать не потребуется.

Проверка содержания claim `roles` в токене локального backend проведена с
тестовым внутренним JWT. Проверка токена конкретного пользователя через
gateway остаётся отдельной интеграционной проверкой.
