## 1. Цель модуля

`[ТРЕБОВАНИЕ · §1]`
Реализовать раздел **«Оценка риска»** модуля «Прогнозирование и оценка биологических рисков» ГИС ББ:
инструмент, позволяющий трём ответственным государственным органам (КСЭК, КВКН, МИО) вносить балльные оценки
по закреплённым за ними факторам риска в разрезе нозологии, территории и периода, а системе — рассчитывать
на сервере интегральный индекс риска и присваивать итоговый уровень риска, включая принудительный
«красный триггер».

Пилотная нозология — **«Бруцеллёз»**, каталог из **46 факторов**.

`[ВЫВОД]` Модуль решает две разные задачи, которые важно не смешивать при проектировании:
1. **Сбор данных** — распределённый между органами ввод баллов;
2. **Расчёт и классификация** — детерминированное серверное вычисление уровня риска.

## 2. Основной бизнес-процесс

`[ТРЕБОВАНИЕ · §3.1, §3.2]` Процесс, как он описан в постановке, состоит из одного замкнутого цикла:

```
Журнал (список оценок в зоне ответственности)
   └─ «Оценить риск» ──▶ Калькулятор (отдельная страница, вне меню)
                             └─ выбор: нозология, регион, [район], панель, период с/по
                             └─ ввод баллов 0–4 только по факторам своей роли
                             └─ «Сохранить оценку» ──▶ серверный расчёт ──▶ возврат в Журнал
```

Параллельный, независимый процесс:

```
Справочник (каталог факторов нозологии)
   └─ Эксперт гос. органа: правка весового коэффициента
                             └─ «Сохранить вес» ──▶ запись в историю изменений
```

`[ПРОБЕЛ]` **В постановке отсутствует какой-либо маршрут документа между участниками:**
нет согласования, утверждения, отправки, возврата на доработку, подписания и рассылки.
Сохранение оценки — терминальное действие одного пользователя. Всё, что относится к межведомственной
маршрутизации, реализовывать нельзя до ответов на `Q-013`, `Q-014`, `Q-021`–`Q-024`.

## 4. Ключевые сущности

Детальная проработка — в [domain-model.md](../02_TECHNICAL/domain-model.md). Здесь — смысловой минимум.

| Сущность | Смысл | Источник |
|---|---|---|
| **Нозология** (`Nosology`) | Заболевание, для которого ведётся каталог факторов. На пилоте — «Бруцеллёз» | Прил. 1 п.2, Прил. 2 п.1 |
| **Регион / Район** (`Region` ADM1 / `District` ADM2) | Территория оценки. Район необязателен — вариант «Обобщённо по региону» | Прил. 1 п.3, Прил. 2 п.2–3 |
| **Фактор риска** (`RiskFactor`) | Элемент каталога нозологии: категория, тип (numeric/binary), вес 1–4, признак RT, шкала 0–4, ответственная роль | Прил. 3, Прил. 4 |
| **Категория фактора** (`RiskFactorCategory`) | Смысловая группа. Для бруцеллёза — 9 категорий | Прил. 3 п.2 |
| **Шкала фактора** (`RiskFactorScale`) | 5 текстовых описаний порогов для баллов 0–4, индивидуально по фактору | Прил. 3 п.7 |
| **Панель** (`Panel`) | Состав оцениваемых факторов: Базовая / Расширенная / Полная. **Состав не задан** (`Q-004`) | Прил. 2 п.4 |
| **Оценка риска** (`RiskAssessment`) | Сохранённый результат: контекст (нозология, территория, панель, период) + баллы + расчётные величины | §3.2, §4, Прил. 2 |
| **Балл по фактору** (`RiskAssessmentScore`) | Значение 0–4 по конкретному фактору в конкретной оценке | Прил. 2 п.7 |
| **Запись журнала** (`JournalRow`) | Строка реестра: нозология, регион (район), период, статус Заполнено/Не заполнено, уровень с цветовым индикатором | Прил. 1 |
| **История изменения веса** (`FactorWeightChange`) | Фиксация правки весового коэффициента | §3.3 |
| **Роль** (`Role`) | Эксперт гос. органа / КСЭК / КВКН / МИО | §2, Прил. 3 п.8 |

`[ВЫВОД]` Сущность «Запись журнала» **не тождественна** сущности «Оценка риска»: журнальная строка может иметь
статус «Не заполнено», то есть существовать при отсутствии оценок. Что именно является «объектом» такой строки,
постановка не определяет (`Q-010`) — это блокирует реализацию журнала как реестра «объектов».

## 5. Основные пользовательские сценарии

### UC-01. Просмотр журнала оценок `[ТРЕБОВАНИЕ · §3.1]`
**Актор:** КСЭК / КВКН / МИО / Эксперт.
Пользователь открывает раздел «Журнал», видит реестровую таблицу с пагинацией и панелью фильтров
(поиск, нозология, регион, период заполнения с/по), применяет и сбрасывает фильтры.
Все роли видят только свою зону ответственности; Эксперт — всё без ограничений.
Ввод баллов в журнале недоступен.

### UC-02. Внесение оценки риска `[ТРЕБОВАНИЕ · §3.2]`
**Актор:** КСЭК / КВКН / МИО (`Q-007` — участие Эксперта не определено).
Из журнала пользователь нажимает «Оценить риск», попадает на страницу калькулятора,
выбирает нозологию, регион, при необходимости район, панель и период заполнения с/по,
проставляет баллы 0–4 по доступным ему факторам и нажимает «Сохранить оценку».
Сервер выполняет расчёт и возвращает пользователя в журнал.

### UC-03. Частичное заполнение `[ТРЕБОВАНИЕ · Прил. 2 п.7]`
Баллы необязательны: индекс считается «по факту заполненности», а доля заполненного отражается
величиной `полнота`. Поведение при нуле заполненных факторов не определено (`Q-005`).

### UC-04. Отклонение чужого фактора `[ТРЕБОВАНИЕ · §3.2]`
Попытка передать балл по фактору вне зоны ответственности роли должна **отклоняться сервером**.
Код ошибки и реакция интерфейса не определены (`Q-028`).

### UC-05. Просмотр справочника факторов `[ТРЕБОВАНИЕ · §3.3]`
**Актор:** все роли. Просмотр каталога факторов нозологии — в пределах своей зоны ответственности,
Эксперту — полностью.

### UC-06. Правка весового коэффициента `[ТРЕБОВАНИЕ · §3.3]`
**Актор:** только Эксперт гос. органа. Изменяет вес фактора, нажимает «Сохранить вес»,
изменение фиксируется в истории. Влияние правки на ранее сохранённые оценки не определено (`Q-012`).

### UC-07. Заполнение демо-данными `[ТРЕБОВАНИЕ · §3.2]`
Кнопка «Демо-данные» случайно заполняет баллы. Доступна **только в среде разработки/тестирования**.
Критерий определения среды и видимость кнопки не описаны (`Q-029`).

### UC-08. Работа со сводной БД `[ПРОБЕЛ · §1.4]`
Функция заявлена, сценарий в постановке отсутствует. Проектированию не подлежит до `Q-006`.

## 6. Что можно строить прямо сейчас, а что нельзя

| Можно проектировать и реализовывать | Нельзя до ответов БА |
|---|---|
| Каталог факторов (46 записей, все атрибуты заданы) | Панели Базовая/Расширенная/Полная (`Q-004`) |
| Роли и запрет ввода чужих факторов на сервере | Матрица «роль → факторы»: два конфликтующих источника (`Q-001`) |
| Формулы индекса и полноты | Отнесение индекса к уровню на границах 5 и 7 (`Q-002`), роль индекса с поправкой (`Q-003`) |
| Правило красного триггера как принудительного уровня | Поведение RT при баллах 1–3 у binary-факторов (`Q-008`) |
| Форма калькулятора, валидация дат и диапазона баллов | Журнал как реестр «объектов» со статусом «Не заполнено» (`Q-010`) |
| Справочник: просмотр и правка веса с историей | Пересчёт ранее сохранённых оценок при правке веса (`Q-012`) |
| — | Раздел «БД» (`Q-006`), ЭЦП/PDF/уведомления/рассылка (`Q-021`–`Q-024`) |
